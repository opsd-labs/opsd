# 故障排查

## 初始化失败

确认：

- 密码文件存在且容器内路径正确；
- 密码文件权限足够严格；
- `--names` 包含用户实际访问 Hub 的域名或 IP；
- 数据目录不是另一个仍在运行的 Hub 正在使用的目录；
- 没有同时运行旧 Hub 和初始化/恢复命令。

查看命令输出和 `docker compose logs hub`，不要把密码、私钥或完整令牌贴入日志工单。

## 忘记安全入口

安全入口不会通过外部 HTTP 接口返回。请优先查找初始化时保存的受保护记录；如果必须从数据目录恢复，先停止 Hub，再由有权限的管理员读取控制库中的 `settings/entrance` 记录。

不要尝试通过扫描根路径或关闭 TLS 来找回入口。

## 浏览器不信任证书

确认浏览器安装的是初始化生成的 CA，而不是随意接受了自签名证书。核对 CA 指纹、访问域名和初始化时的 `--names` 是否一致。

反向代理场景还要检查代理是否保留了完整的 `/{安全入口}/` 路径和正确的 HTTPS Origin。

## Agent 无法注册

按顺序检查：

1. Hub 的 `8444` 端口对节点可达。
2. Agent 使用的是当前 Hub 的 CA，而不是旧环境的 CA。
3. 注册令牌没有过期、重复使用或写错。
4. Hub 的域名/IP 与 Agent 的连接配置一致。
5. 节点系统时间没有严重偏差。
6. 注册后 Agent 是否切换到 mTLS 身份材料并重连。

注册端点不需要安全入口，但除该精确端点外的管理 API 仍需要安全入口。

## Agent 注册后反复离线

查看 Hub 和 Agent 两侧日志，重点检查：

- 证书有效期和 CA 指纹；
- 节点到 `8444` 的长连接是否被代理或防火墙中断；
- Agent 数据目录是否可写；
- 节点主机时间是否同步；
- Hub 是否被重复启动导致数据目录锁冲突。

## 反向代理返回 404 或请求被丢弃

常见原因是代理把安全入口路径裁掉了，或把控制台请求转发到错误的 Origin。直接访问不带入口的根路径本来就不会返回普通页面；请使用初始化输出的完整地址。

## 健康检查失败

容器健康检查访问的是回环 `65534` 端口：

```bash
docker compose exec hub opsd-hub probe
docker compose ps
docker compose logs --since=10m hub
```

不要把 `65534` 映射到公网。若 Hub 未启动，先检查数据目录、权限、证书材料和端口冲突。

## 端口冲突

通过环境变量修改 Compose 在主机上的绑定端口：

```bash
export OPSD_CONSOLE_PORT=36535
export OPSD_AGENT_PORT=18444
docker compose up -d
```

同时更新 `OPSD_ORIGIN`、反向代理和 Agent 连接配置。端口号本身不是安全措施。

## 数据目录或恢复问题

备份和恢复前必须停止 Hub。确认：

- 备份目录以只读方式挂载到恢复命令；
- 恢复目标是全新或明确清空的数据目录；
- Compose 配置、镜像摘要、CA 和域名保持一致；
- 恢复后重新验证管理员登录和 Agent 重连。

恢复不会带回浏览器会话和旧注册令牌。
