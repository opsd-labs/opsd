# opsd 后端重规划与前端精简

本文件是 2026-09 重新规划后的实施蓝图，替代此前以「落地设计稿」为重心的方案。
设计语言（中性底 + 局部靛蓝、36px 行高、轻底状态标签、并列详情）继续有效，
但已降级为前端实现前提，不再做多布局/多配色探索。

## 需求边界

| 项 | 决定 |
|---|---|
| 控制台 | 首页展示所有节点状态 |
| 一级菜单 | 控制台、节点、数据库、容器、防火墙、存储、设置 |
| 堡垒机 | **终端 + 文件**融入节点页 |

| 分享页 | 公开只读状态面，深度参考 mosona-manager |
| 分享页 API | 供 Grafana 这类面板消费 |

## 后端能力

### B1 节点指标、历史曲线与延迟

Agent 定时（15s）采样并**主动上报**，复用既有 mTLS 通道，不新增 node_exporter。
指标：CPU（总/每核/负载 1·5·15）、内存与交换、每挂载点用量与 inode、磁盘 IO、
每接口收发速率与错误、运行时长、进程数、TCP/UDP 连接数、时钟偏移。

- 协议：新增 `Frame::Metrics`；`NodeCapabilities` 增 `metrics`。无能力位时显示「未上报指标」，**不显示 0**。
- 延迟探测：Agent 对已登记节点做 ICMP/TCP 探测，结果进时序库，支撑分享页与线路质量观察。
- **存储**：**指标历史保存在控制库中并分层降采样**，而不是引入 InfluxDB。
  理由：12 节点 × 每 15 秒一次采样 ≈ 每天 7 万条原始记录，SQLite/MariaDB 配合降采样完全够用，
  而 InfluxDB 会带来一个必须备份、必须监控、必须先于主控启动的额外组件。
  分层保留：原始 15s × 7 天；5 分钟桶 × 90 天；1 小时桶 × 1 年。桶内标量取平均、明细取最后一次。
  这是对原方案的**有意偏离**：原方案要求在主控 Compose 内加入 InfluxDB 2.x。
  若日后规模超出控制库承载能力，`src/hub/metrics.rs` 的 `ingest`/`decimate` 是唯一需要替换的接缝，
  写入与查询的其余部分不受影响。
- **API**：`GET /api/v1/metrics/overview`（全部节点最新值）、`GET /api/v1/nodes/{id}/metrics?from=&to=&step=`（历史曲线）、
  `GET /api/v1/metrics/status`（各层级记录数与最早时间）。
- **边界**：采样失败上报 `error` 且不写历史；离线区间曲线**断开**不补零；时钟偏移超 60 秒时提示（该估计含单向时延，只用于识别明显偏差）。
  前端另有四种状态互不冒充：未上报指标（无能力位）、尚未上报、采集失败、数据陈旧。

### B1.1 延迟探测

Agent 侧对已登记节点做周期探测，结果**进同一套时序存储**，用于线路质量观察。

- **不猜地址**：目标列表由主控下发（只有它知道全部节点），带版本号走任务机制，
  因此会落盘、重启后仍在；目录没变就不重发。优先探测**覆盖网地址**——
  那是节点之间真实的转发路径，也是 Galera 复制实际走的路。
- **方式**：默认 ICMP（`ping -n -c 1 -W 3`），不产生任何服务端日志，也不需要额外特权；
  只有显式给出端口的对端才走 TCP 握手计时（会在对端服务上留下连接记录，因此不作为默认）。
- **间隔 60 秒**：线路质量不需要 15 秒的粒度，更低的频率让调度抖动不会混进延迟数字。
  探测**独立于采样循环**（一轮要连十几个对端，串在采样里会把采样节奏带偏），
  采样只取"最近一轮已完成的结果"，并带上 `probed_at` 说明这个数字是什么时候测的。
- **没测到就不是 0**：`latency_ms` 为 `None` 表示没有测到，`0.0 毫秒` 是"同机"。
  三者严格区分：**网络不通**（100% 丢包）、**本机没有 ping 命令**（测不了）、
  **测到了**。把它们混成一个 0 会让"线路断了"看起来像"线路很好"。
- **降采样**：延迟是按对端平均的标量，因此在 5 分钟与 1 小时桶里同样取平均——
  像其它标量一样，而不是像磁盘明细那样只留最后一次，否则曲线的抖动会被放大成假趋势。
  一次丢包不会把曲线打断（保留上一次的数值），但**一旦明确不可达就以最新事实为准**。

界面在节点详情的「线路质量」表里展示（对端、地址、方式、延迟、结果与原因）。

**与原方案的取舍**：原方案写的是"支撑分享页与线路质量观察"，实现时**只做了后半句**。
延迟矩阵必然带出节点之间的内部地址（覆盖网 `100.100.201.x`），把它放到公开分享页
等于公开内部拓扑；分享页的字段白名单本意就是只放"可以公开的事实"，
因此这一项不进分享页。这是有意的偏离，不是遗漏。

### B2 堡垒机：终端与文件

统一流会话，`StreamOpen` 携带 `kind` 与 `target`：

```
kind   = container_terminal | host_shell | file_list | file_read | file_write
target = Container{ id } | Host{ shell, workdir } | Dir{ path } | File{ path, offset, limit }
```

**为什么文件操作必须是结构化的**：如果让界面拼 shell 命令去 `ls`、`cat`、`rm`，
主控既无法审计（只能记录"执行了一条命令"）也无法约束（只能靠字符串黑名单）。
每个动作拆成独立操作后，路径在 Agent 侧强制校验，且**不经过任何 shell**。

**读走流、写走任务的划分**：列目录、读文件、下载是只读的，走流式请求-响应并记审计，
**不进任务表**（否则任务列表会被浏览操作淹没）；上传、删除、重命名、改权限、建目录
是变更操作，走既有任务机制，因此天然带幂等键、事件与结果，并参与节点变更锁。

#### 四条防线

| 防线 | 做法 |
|---|---|
| 路径规范化 | 只接受绝对路径，词法展开 `.` 与 `..`，并**先解析已存在部分的符号链接**再校验，防止通过目录软链逃逸 |
| 拒绝符号链接叶子 | 打开文件带 `O_NOFOLLOW`；无法用该标志的操作（列目录、删除、重命名、改权限）显式检查 `symlink_metadata` 并改用 `lchown` |
| 硬禁前缀 | `/proc`、`/sys`、`/dev`、`/run/docker.sock`，以及**运行时注入**的 Agent 数据目录与 PKI 目录（不写死） |
| 体积上限 | 单次读取 1 MiB、单文件 64 MiB、递归删除 1 万条、列目录 5 千条 |

递归删除另外要求 `recursive` 与 `confirmed` **同时**为真。前缀比较按组件边界进行，
因此 `/procx` 不会被误判为 `/proc` 的子路径。

#### 上传的原子性

上传分两步：先把内容分块写进**由目标路径推导出的暂存文件**，再提交 `FilePut` 任务，
由 Agent 核对摘要与大小后才原子改名覆盖目标。任何不符都会失败，**原文件保持原样**。
校验失败**不删暂存内容**——任务可能因网络或主控重启而重试，删掉就没法重试了；
暂存文件名确定，下次上传会直接覆盖它。

#### 宿主机终端

Agent 侧只允许白名单内的 shell（`/bin/bash`、`/bin/sh`），并 `env_clear()` 后重新注入
最小环境，因此终端里看不到节点身份与主控地址；起始目录同样过路径闸门。
会话建立与结束都写审计（谁、哪个节点、起止时间、传输字节）。

**注意**：宿主机终端以 Agent 的权限运行，能做的事与 root 相当。首版只有本地管理员一个角色，
因此没有更细的授权划分；引入多用户时必须先补上按节点的终端授权。

### B3 数据库只读运维视图

**这一页回答的问题是「五节点 Galera 集群现在到底怎么样」，而它必须能回答「不知道」。**

新增 `Action::DbInspect {}`（**不带任何参数**）与 `database` 能力位。四个分区各自独立采集，
互不牵连——ProxySQL 连不上时 Galera 部分仍然有效：

| 分区 | 内容 |
|---|---|
| Galera | `wsrep_cluster_status/size/local_state{,comment}/ready/connected/desync`、流控暂停比例、收发队列、`last_committed`、认证冲突计数、集群 UUID、节点 UUID、`sst_donor`、组件版本、成员地址 |
| 主机侧 | 版本、主机名、`server_id`、uptime、连接与活跃线程、`read_only`、binlog 位点 |
| ProxySQL | `runtime_mysql_servers`（hostgroup/status/weight）、`stats_mysql_connection_pool`（连接与延迟）、`stats_mysql_query_digest` 的**摘要哈希与计数** |
| 备份链路 | hourly/daily/weekly 三层各自：最近成功时刻与距今、体积、归档个数、`SHA256SUMS`、归档头、定时器下次触发 |

三条硬约束：

1. **只读且语句固定**。语句是 Agent 里的常量，主控无法影响它们，因此没有 SQL 经过网络，
   也就不存在把这条通道变成任意查询通道的可能。不建库、不建用户、不改配置、
   不触发 SST、不 kill 查询。
2. **凭据不出本机**。密码由 Agent 从运维既有的 0600 秘密文件里读
   （`/root/galera-secrets/cluster-secrets.env` 的 `EXPORTER_PASSWORD`、
   `/root/proxysql-secrets/admin.env` 的 `PROXYSQL_ADMIN_PASSWORD`），
   只经子进程环境进入容器内的客户端，既不上传主控也不进审计。
   权限校验不合格（组或其他用户可读）时**拒绝读取**。
   Agent 侧配置 `db-inspect.json` 里只有路径与账号名，因此不需要第二套秘密分发机制。
3. **连不上就是未知**。连不上、没权限、没配置都产出「未知 + 原因」。
   界面绝不把它显示成 0 或「正常」：把采集失败显示成一片平静的绿色，
   是运维视图最危险的假象。

**判断集中在控制台，且阈值与告警规则逐条对齐**——否则控制台说正常、告警说异常，
运维人员就再也不能相信任何一个：

| 判断 | 阈值 | 对应告警 |
|---|---|---|
| 集群成员数不等于期望值 | 与配置比（默认 5） | `GaleraClusterSizeMismatch` |
| 非 Primary、Ready/Synced 不成立 | — | `GaleraNotPrimary`、`GaleraNodeNotReadyOrSynced` |
| 接收队列积压 | > 32 | `GaleraReceiveQueueHigh` |
| 流控暂停比例 | > 0.01 | `GaleraFlowControlPausedHigh` |
| 认证冲突 | > 0 | `GaleraCertificationConflicts` |
| ProxySQL writer | ≠ 1 | `ProxySQLWriterCountInvalid` |
| ProxySQL 备用 writer | < 4 | `ProxySQLBackupWritersInsufficient` |
| hourly 备份过期 | > 90 分钟 | `HourlyBackupStale` |
| daily 备份过期 | > 26 小时 | `DailyBackupStale` |

**跨节点一致性检查**是这一页真正的价值所在——只有把节点放在一起才能发现的问题：
集群 UUID 不一致（已分区）、节点 UUID 重复（数据目录被克隆）、
各节点看到的成员数不一致（尚未收敛）、健康成员少于多数派。

两个刻意的克制：

- **只看了一部分成员时不下多数派结论**：少巡检几台不等于它们不健康，
  把"没看到"当成"不健康"会凭空造出一堆假故障；
- **未知不参与严重程度排序**：`tone` 只描述已经确定的问题，未知单独计数并列出原因
  （连同"节点当前离线，以下是 7200 秒前的巡检结果"这种时间点说明）。

备份产物的正确性上，只读巡检只能做到**检查归档头是不是 age 格式**——解密私钥按设计
不在节点上，因此这里不做解密校验，界面上也不谎称做过。

审计记录「谁在什么时候对哪台数据库做了一次只读巡检」，类别为 `数据库`，
**不含 SQL 正文与凭据**。巡检结果缓存在主控内存中，不落库：它是"此刻的状态"，
落库只会留下一份会被误读为现状的历史快照。

**明确不做**：建库、建用户、改配置、触发 SST、慢查询 kill、查询正文展示。

### B4 存储预检与集群纳管

**预检是只读的，判断集中在控制台完成。** Agent 只带回事实，不跑任何判断，
因此结论可以被复核；本机也不会有任何写操作。

Agent 侧（`Action::HostInspect`，新增 `hostinfo` 能力位）采集：
主机（发行版/内核/CPU/内存/uptime）、块设备（以 `lsblk -J -O -b` 为唯一来源）、
逐盘风险标记、网卡与链路速率、既有对象存储痕迹，以及可选的 SMART 摘要。

**「只批准没有任何先前使用痕迹的磁盘」** 是预检的核心安全立场。以下任一成立即排除：

| 标记 | 含义 |
|---|---|
| `system_disk` | 承载 `/`、`/boot`、`/usr`、`/var` 之一（分区风险会归到整盘上） |
| `has_data` | 已挂载**且**有文件系统 |
| `unmounted_filesystem` | 有文件系统但未挂载——很可能是数据盘，不挂载无法确认 |
| `has_partitions` | 存在分区表，也是"有人用过"的证据 |
| `lvm_member` / `raid_member` / `luks` | 属于 LVM、软 RAID 或加密卷 |
| `removable` / `zero_size` | USB 设备，或容量为 0 的空读卡器 |

用过但已清理的盘请先 `wipefs` 再重新盘点——清理后就满足上述条件。

**结论式报告**（`GET /api/v1/storage/readiness`）由纯函数生成，因此可以被穷举测试：

- 逐节点结论：适合 / 需要先处理 / 不适合 / **待采集**，每条都附具体原因；
- 一致性检查：候选节点 ≥ 4、每节点磁盘数量一致、容量差异 ≤ 25%、介质类型一致、
  链路 ≥ 100 Mbps、采集完整性；
- 推荐拓扑：节点数 × 每节点盘数 × 最小盘容量，并按 MinIO 默认规则给出校验盘数量
  （4–7 块校验 2，8 块及以上校验 4）与扣除校验后的可用容量。

**三条硬规则**：

1. **不猜**：没有盘点结果的节点标为「待采集」，绝不判为不适合；
2. **每个结论都有原因**：界面直接展示原因，而不是只给一个分数；
3. **不把信息不全当没问题**：任何采集缺口（含 SMART 未采集）都会把结论降级为「需要先处理」，
   且不会给出推荐拓扑。

`POST /api/v1/nodes/{id}/host-inspect` 触发盘点，走任务机制以便看到执行结果；
盘点结果缓存在主控内存中，不进节点记录——它体积较大、变化很慢，且只有预检会读。

### B4.1 存储集群部署与纳管

**预检结论只有在被固化成"将要发生什么"之后才能执行。** 因此部署分成三步，
每步之间都有人可以停下来的位置：

| 步骤 | 接口 | 是否碰节点 | 产出 |
|---|---|---|---|
| 保存定义 | `PUT /api/v1/storage/clusters` | 否 | 集群名、节点编号、固定镜像标签、endpoint、S3 密钥 |
| 生成计划 | `POST /api/v1/storage/plans` | 否 | 逐节点的设备路径 + 计划时容量 + 挂载点、指纹、5 分钟有效期 |
| 执行计划 | `POST /api/v1/storage/plans/apply` | 是 | 逐节点串行下发「磁盘准备 → 容器部署」两个任务 |

**定义只校验形态，计划才核对现实。** `validate_spec` 只看定义自身是否自洽
（名称合法、节点 ≥ 4 且不重复、标签是具体 release、密钥长度），因此可以先于节点存在而保存；
节点是否存在、是否在线、是否已盘点、磁盘是否干净，全部留到 `build_plan` 阶段核对——
那时才有真实的盘点结果可用。

计划里显式记下**指纹**（设备集合的哈希）与**有效期**。执行前重新校验：

- 指纹不再匹配（换了盘、加了分区、容量变了）→ 计划作废，要求重新生成；
- 超过 5 分钟 → 计划作废；
- 任一节点离线或失去盘点结果 → 整份计划拒绝执行；
- `destructive` 为 true 时必须带 `acknowledge_destructive: true`，否则 400。

**逐节点串行、失败即阻断**：某台节点的磁盘准备失败时，后续节点一律不再执行——
宁可停在一个明确的中间状态，也不要出现"三台格式化成功、一台没动"的静默半成品。

节点侧再核对一次现实（见 `src/agent/storage.rs`）：设备存在、容量与计划一致、
仍然没有任何使用痕迹、挂载点仍在 `/data` 之下。这是刻意的冗余判断，
且与主控用的是**同一套判据**（`verify_device`），避免两处判定各自漂移。

**S3 密钥不回传**：`GET /api/v1/storage/clusters` 只返回 `has_secret_key`，
密钥仅在服务端生成 Compose 时使用；界面从不需要读它。

集群内的桶与用户走 `POST /api/v1/storage/buckets`、`POST /api/v1/storage/users`，
状态查询走 `POST /api/v1/storage/status`，均通过 `mcli` 在节点侧执行并写审计。


### B5 审计与任务

新增 `audit_log`（控制库 `audit` 桶）：时间、管理员、节点、类别
（会话/文件/数据库/存储/防火墙/容器/分享页/主题）、目标、结果、来源 IP、字节数、时长。
`GET /api/v1/audit?from=&to=&node=&category=&result=&limit=`，默认 200 条、硬顶 1000 条，保留一年。

**审计只记录对象与结果，不记录内容**：文件正文、命令全文、凭据与 SQL 正文一律不进审计——
审计本身要能被普通管理员查阅，就不能成为新的泄漏面。

任务仍是变更类操作的唯一入口，状态机不变；任务不再占用一级菜单。

### B6 主控栈

控制存储默认 SQLite、可选独立 MariaDB，**不引入 Redis**。新增 InfluxDB 2.x（见 B1）。
端口与门禁按「安全入口」一节调整。

## 安全入口（访问门禁）

- 浏览器面默认端口 **65535**（Agent mTLS 通道 8444 不变）。
- 控制台唯一入口 `{ip}:65535/{安全入口}/`。首段不匹配 → **丢弃连接，不产生任何 HTTP 响应**。
- 安全入口在 `hub init` 首次初始化生成，写入配置并**输出到初始化日志**（与 CA 指纹一起）。
- 16 位，大小写字母 + 数字 + 符号，CSPRNG 生成。符号集建议取 URL-unreserved 的 `-._~`，
  避免从日志复制时触发百分号编码问题。
- 设置页可修改，立即生效；旧地址失效并保留 **60 秒宽限**，宽限结束强制重新登录。
- 门禁放在**最外层连接处理**，不在路由层：不匹配时不生成响应、直接关闭连接，
  消除 404/400 之类可区分信号。若框架无法完全静默，退化为「空响应后立即关闭」，
  但**禁止**任何可区分的错误页；此点必须实测确认。
- 控制台静态资源与 API **统一挂在 `/{安全入口}/` 之下**（含 `/api/v1/*`、SSE、WebSocket）；
  前端 base 用相对路径，API 前缀运行时注入。
- 门禁**两类放行**：安全入口（控制台）与分享令牌（分享页）。其余一律丢弃。
  唯一的例外是 Agent 注册路径，见下方说明。
- 路径比较用**常量时间比较**；入口不匹配的请求加**速率限制**（超限后加固定退避）。
- **访问日志脱敏**：安全入口与分享令牌明文不得进入日志或错误信息。
- 健康检查走**独立内部监听或仅 loopback**，既不被门禁遮蔽，也不成为绕过门禁的探针。
- 安全入口**不是认证**，只降低探测面。Cookie（HttpOnly）、CSRF、Origin 校验三者一个不能省。

### Agent 注册的例外

`POST /api/v1/enroll` 必须发生在 Agent 拿到客户端证书之前，因此不可能走 mTLS 通道。
它挂在入口前缀**之外**的根路径上，并列入 `entrance::AGENT_PATHS` 白名单。

- 凭据是一次性、十分钟有效、随机的注册令牌，加上 Agent 侧 CA 指纹核对，不依赖入口隐蔽性。
- 代价：该路径返回 401 而不是直接断连，扫描者可据此推断这是一个 opsd 主控。
- 因此白名单**逐条精确匹配**，绝不写成前缀；新增条目必须逐条评估同样的代价。

## 分享页与分享页 API

分享页面向他人查看，与控制台**完全隔离**。隔离不是靠约定，而是靠三条可验证的机制：

1. **Cookie 路径隔离**：控制台会话 Cookie 的 `Path` 限定在 `/{安全入口}/` 之下，
   浏览器**不会**把它发给分享路径。已在真实浏览器里核对请求头确认。
2. **独立令牌**：分享面有自己的路径 `/share/{令牌}/` 与自己的令牌，不经过安全入口，
   门禁按令牌是否有效决定放行还是丢弃。
3. **字段白名单**：公开响应由 `PublicNode` 结构体定义，**默认拒绝**。
   永不下发公网地址、EasyTier 地址、SSH 端口、凭据、容器/防火墙/数据库细节、终端入口、任务与审计内容。

**不经安全入口**的理由：分享页受众是外部、需要可转发；安全入口受众是自己、需要保密。
若把分享页塞进安全入口之下，等于把入口随链接扩散给所有拿到链接的人。

### 凭据分工

| 路径 | 凭据 | 用途 |
|---|---|---|
| `/share/{令牌}/` | 分享令牌 | 分享页本身 |
| `/share/{令牌}/data/` | 分享令牌 | 分享页读取数据（令牌本就在地址里，页面上藏不住密钥） |
| `/share/{令牌}/api/v1/public/` | 分享令牌 **+ API Key** | 供 Grafana 等面板消费 |

令牌决定"能读哪些节点"，API Key 决定"是否有权以机器方式读取"；两者的节点范围**取交集**。
明文令牌与密钥都只在创建响应中出现一次，控制库只保存 SHA-256 摘要。

### API

| 接口 | 说明 |
|---|---|
| `GET /api/v1/public/summary` | 节点数与在线数 |
| `GET /api/v1/public/nodes` | 脱敏节点列表 |
| `GET /api/v1/public/recent/{id}` | 单节点最新状态 |
| `GET /api/v1/public/records?node=&from=&to=&step=` | 历史曲线 |
| `GET /api/v1/public/metrics` | **Prometheus 文本格式**，接入 Grafana 的推荐方式 |

指标名：`opsd_node_online`、`opsd_node_cpu_usage_percent`、`opsd_node_memory_used_bytes`、
`opsd_node_memory_total_bytes`、`opsd_node_disk_used_bytes`、`opsd_node_disk_total_bytes`、
`opsd_node_load1`、`opsd_node_network_{receive,transmit}_bytes_per_second`、`opsd_node_uptime_seconds`。
标签只有 `node` 与 `display_name`，**不含地址**。缺少采样的节点不输出样本行，面板上表现为断档而不是 0。

**不建议**让 Grafana 直连控制库或时序库：会绕过凭据校验、暴露内部数据、破坏字段白名单。

### 与原方案的取舍

原方案把访问模式列为「公开 / 私密（需登录）/ 临时链接」。本轮实现的是
**公开（持令牌即可读）+ 有效期 + 节点范围限定**，而**没有**实现"分享页读取控制台会话"这一模式：
那需要让分享面接收控制台 Cookie，与"分享页拿不到任何控制台凭据"这条更重要的保证直接冲突。
"私密"由「关闭分享面 + 仅控制台可见」表达。若确需访客登录，应引入**分享面独立的访问码**，
而不是复用控制台会话。

## 主题系统

两条主题线的粒度**刻意不同**，这不是实现偷懒，而是风险差异决定的：

| | 控制台主题 | 分享页主题 |
|---|---|---|
| 粒度 | **令牌级**：颜色、圆角、密度、字体、明暗 | **包级**：完整前端包 |
| 替换范围 | 不替换组件结构 | 替换整个分享页前端 |
| 安装方式 | 提交 `theme.json` 清单（JSON） | 上传 zip 包 |
| 理由 | 含终端/任务/表单/键盘交互，结构替换风险过高 | 纯只读展示，隔离后可自由替换 |

参考项目 Komari 也明确约定主题不替换 `/admin` 与 `/terminal`，只替换公开监控面。

一个主题通过 `surfaces: ["share"] \| ["console"] \| ["share","console"]` 声明覆盖哪个面；
**同时覆盖两者的主题也是合法的**。设置页提供两个独立选择器：分享页主题列表只列含 `share` 的主题，
控制台主题列表只列含 `console` 的主题；内置 `default` 不可删除也不可被占用。

### 安全边界

- 首版只支持 `configuration.type = "managed"`（由控制台生成表单）。
  **`raw` 明确不做**——它允许主题在管理区渲染自带 HTML，等于在控制台里执行第三方代码。
- 主题包由主控**自行计算 SHA-256 摘要**并记录，包内声明不作数；仅支持**本地上传安装**，
  不接在线市场、不自动远程拉取。
- 解压时拒绝越界路径（`..`、绝对路径，用 `enclosed_name` 判定）并限制解压后总体积，防压缩炸弹。
- 令牌值写进 CSS 自定义属性，因此校验会拒绝 `;` `{}` `<>` 换行反斜杠，
  以及 `url(`、`@import`、`expression(`、`javascript:`、`/*` 等能引发外部请求或代码执行的写法。
- 分享页主题运行在 `/share/{令牌}/` 之下，与控制台**不同路径**；控制台会话 Cookie 的 `Path`
  限定在安全入口之下，因此主题拿不到它。主题资源与页面都带独立 CSP：
  `default-src 'none'; script-src 'self'; connect-src 'self'; frame-ancestors 'none'`，默认禁止外联。
- **分享页主题的配置是公开可读的**（与 Komari 的 `theme_settings` 同理）。
  设置界面与文档都必须提示：不得放入密钥、Token 或私密地址。

### 接口

| 接口 | 说明 |
|---|---|
| `GET /api/v1/themes` | 已安装主题列表 |
| `GET/PUT /api/v1/themes/active` | 两个界面各自启用的主题与设置；`console` 响应带令牌供界面应用 |
| `POST /api/v1/themes/console` | 安装控制台主题（JSON 清单） |
| `POST /api/v1/themes/share` | 安装分享页主题（zip 原始字节，独立体积上限） |
| `DELETE /api/v1/themes/{short}` | 卸载；删除启用中的主题会自动回落到内置 |
| `GET /share/{令牌}/data/theme` | 公开的主题与设置 |
| `GET /share/{令牌}/theme/{路径}` | 主题资源，带独立 CSP |

控制台主题的应用方式是在 `:root` 与 `:root[data-theme="dark"]` 上写入 CSS 变量，
与内置令牌的层叠方式完全一致，因此不触碰组件结构。

- 默认构建**禁止防火墙写入**；`experimental-firewall` 仅供隔离实验室构建。本规划不改变这一限制。

## 已落地的实现要点

安全入口一节对应的实现分散在几处，改动时需一并核对：

| 位置 | 职责 |
|---|---|
| `src/entrance.rs` | 生成、校验、常量时间比较、首段提取、按来源限速、门禁 `Gate`、`AGENT_PATHS` 白名单 |
| `src/transport.rs` | 按连接构造门禁；`serve_plain` 提供仅回环的健康监听 |
| `src/hub/mod.rs` | `init` 生成并打印入口；`serve` 把静态资源与 API 统一 `nest` 到 `/{入口}`、把 Agent 注册挂到入口之外的根路径；`probe` 子命令 |
| `src/hub/api.rs` | `GET/PUT /api/v1/settings/entrance` |
| `web/src/api.ts` | `basePath()` / `apiPath()`：从地址首段推导前缀，SSE 与 WebSocket 都经过它 |
| `web/vite.config.ts` | `base: './'` 与开发代理的入口前缀重写 |

三个易踩的点：`nest` 不匹配裸的 `/{入口}/`，因此额外注册了根路由；
`generate()` 的首字符必须避开 `.` 与 `-`，否则会产出通不过 `validate()` 的入口；
Agent 注册必须在入口之外挂载，否则 Agent 无法首次接入。

### 只读巡检的判定分散在两处，改动时要一起核对

| 位置 | 职责 |
|---|---|
| `src/agent/database.rs` | 固定语句、凭据读取与权限校验、容器内客户端调用、纯解析函数、备份目录与定时器事实 |
| `src/hub/database.rs` | 阈值判定（与告警对齐）、跨节点一致性检查、结论与未知计数 |
| `src/hub/channel.rs` | 巡检结果进内存缓存并广播 `database` 事件 |
| `web/src/databasePresentation.ts` | 「未知不等于 0」的展示口径，单元测试守在这里 |

阈值**只在 `src/hub/database.rs` 里写一次**。Agent 只带回事实与 `expected_cluster_size`，
不做判断——判断集中在控制台，才能被复核，也才不会出现两处阈值各自漂移。
