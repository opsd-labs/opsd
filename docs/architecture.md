# 架构说明

## 组件

```text
浏览器
  │ HTTPS + 安全入口 + 会话/CSRF
  ▼
Hub ─────────────── 控制库、任务、审计、聚合结果
  │
  │ 8444 / mTLS，Agent 主动连接
  ▼
Agent ───────────── 节点本机 Docker、主机、数据库和运维工具
```

Web 控制台和 Hub 一起发布。Hub 不需要进入节点网络主动连接 Agent，节点只需能够主动访问 Hub 的 mTLS 端口。

## Hub

Hub 提供：

- 管理员认证和会话；
- 安全入口门禁；
- Agent 注册、证书和节点目录；
- 任务下发、结果聚合和事件广播；
- 指标、数据库和存储结果的集中展示；
- 分享令牌、主题、审计以及备份恢复；
- HTTP API 和 Web 控制台静态资源。

默认控制台监听 `65535`，健康检查监听容器回环的 `65534`。健康检查不是外部管理入口。

## Agent

Agent 运行在被管理节点上，负责：

- 主动建立和维护 mTLS 连接；
- 采集主机、Docker、指标、数据库和存储事实；
- 在本机执行结构化任务；
- 使用节点上已有的权限和秘密文件；
- 将结果和错误原因返回 Hub。

Agent 不应将不必要的秘密上传 Hub。数据库巡检密码等凭据只在节点本地进入客户端进程环境。

## 数据流

1. 管理员在 Web 控制台发起查询或任务。
2. Hub 验证会话、CSRF、权限和请求结构。
3. Hub 通过对应 Agent 的 mTLS 通道下发结构化任务。
4. Agent 在本机执行固定动作或受控命令。
5. Hub 校验结果、记录审计并更新内存缓存或控制库。
6. Web 获取聚合后的结果，并明确区分未知、过期和异常。

## 信任边界

- 浏览器到 Hub：HTTPS、Origin、Cookie 和 CSRF 共同保护控制面。
- Agent 到 Hub：双向 TLS，注册前使用一次性短时令牌建立身份绑定。
- Hub 到节点：不存在反向 SSH 或 Docker socket 访问；节点侧执行由 Agent 负责。
- 公开分享面：只允许公开字段和专用令牌，不继承管理会话。
- 节点本地秘密：由 Agent 按权限读取，不进入 Hub 控制库和普通审计正文。

## 存储

默认控制库是 `data/control.db`。可通过 `OPSD_DATABASE_URL` 使用独立 MariaDB，但当前版本不支持在线跨库迁移，也未完成真实 MariaDB 回归。

运行期变化快的指标、数据库和主机盘点结果部分保留在 Hub 内存缓存中，并带采集时间；历史任务、控制记录和审计数据进入控制库。
