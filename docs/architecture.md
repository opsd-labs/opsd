# 架构说明

## 组件与依赖方向

核心维护节点身份、网络目录、双线路控制连接、任务恢复、认证审计、插件管理和只读输出；业务插件调用成熟程序。普通防火墙管理、数据库巡检和文件能力沿用原有边界。

| 层级 | 职责 | 调用方向 |
| --- | --- | --- |
| Hub 核心 | 认证、节点、任务、网络期望状态、插件进程与输出 API | 通过 mTLS 与 Agent 通信，通过 Unix socket 托管插件 |
| Agent 核心 | 本机事实、网络期望状态执行、单一任务队列 | 按固定插件版本启动节点程序 |
| ET 插件 | 现有 ET Web 的实例、配置、关联与运行信息 | 现有 ET Web；不重新部署它 |
| Docker 插件 | Portainer 引导安装及日常 Docker 集成 | Portainer Server → 普通 Agent → Docker Engine |
| Silo 插件 | 存储适合度、明确选盘、部署进度、桶和用户 | 依赖 Docker 插件部署容器，使用 Silo 与 mcli |

Hub 容器不挂载 Docker socket。需要部署 Portainer Server 时，先手动接入 Hub 宿主机 Agent，并在节点页面将其指定为控制机。C091 不会因此自动安装 Agent。

## 节点身份与地址

注册只填写名称与安装方式。Agent 网卡、已认证连接的实际来源、明确关联 ET 实例的 STUN 信息分别保存来源与时间。地址归属于节点证书身份；改名或地址变化不创建新节点。

本机公网地址、公网出口与探测结果分开记录。NAT 出口只进入来源白名单，不直接成为可入站的服务地址。ET 地址必须来自所选实例，并与对应 Agent 的实际接口核对；名称相同不构成身份关联。ET Web 不可用时保留已知目录，错误和采集时间说明新鲜度，不停止已经运行的网络。

每个逻辑节点可同时维持公网与 ET 两条连接，各自记录代次、心跳、往返延迟与错误。公网可用且稳定 15 秒后优先，否则使用 ET；拨号地址改变时仍验证原 Hub 身份。两条线路共享本地任务库和一个执行队列，重投使用原任务编号，不能执行两份任务。

节点与 Hub 的控制连接、节点之间的公网／ET 周期探测、ET 实例的直连／中继信息分别展示。ICMP 无回应不等于控制连接中断，也不等于 ET 使用中继。

### 自动互信白名单

Hub 生成带版本的完整期望状态，Agent 只持久化和追赶最新版，不为每次变化创建普通任务。可信来源为未撤销 OPSD 节点的公网 IPv4／IPv6 地址，以及同时匹配实际 ET 入接口和选定网段的流量；覆盖主机与 Docker 转发路径。现有默认策略与其他规则保留，仅维护 OPSD 归属的链和跳转。

地址替换先保留新旧来源。新认证公网路径确认替换、当前在线节点应用包含新旧地址的集合后，再收敛旧来源；离线不构成撤销。共享出口按所有有效节点的集合计算。STUN 暂时无结果不清空旧地址，尚未获得新路径确认的旧来源继续保留。

该能力独立于原来的实验性通用防火墙写入。Ubuntu 24.04 上 nftables、iptables、UFW 和 firewalld 2.1.1 的隔离行为已通过；带 owner 独占保护的 firewalld 规则表当前明确拒绝接入，不关闭保护或重载用户规则。无法读取规则、对象名称无法安全引用及 Docker Agent 不能写宿主机策略的情况显示错误，不假报已应用。

整段 ET 互信也意味着，撤销 OPSD 证书和公网来源不等于隔离 ET 成员；ET 成员隔离仍需经 ET 插件处理。

## 插件进程、版本和秘密

插件放在同仓独立目录，包中包含清单、平台程序、页面及业务接口定义。核心插件接口版本为 1；业务契约分别放在 plugins/{插件}/api.json。核心只登记插件编号、版本、依赖、操作、目标与结果，不增加 Silo 桶或 Portainer Stack 专用任务类型。

后端通过私有 Unix socket 接收核心已认证的请求。socket 使用短路径、权限受控的临时目录，避免数据目录较长时超过 Linux 路径上限。节点程序由 Agent 下载后按 plugin/version 保存，通过 JSON 标准输入执行；不把秘密放进进程参数。

任务同时固定本插件及其依赖版本。升级切换新请求与页面，已受理任务继续使用原程序；活动任务引用的包不能卸载。禁用停止新操作，卸载只移除程序包，托管数据和秘密分别保留。Hub 或节点在写入途中重启时，执行中的结果标为待核实，不自动把危险操作重新提交。

普通配置只允许清单声明的键。凭据保存在受保护的独立秘密文件，浏览器只读取名称；节点只收到清单声明的必要秘密。服务私钥在节点生成，Hub 只签发绑定 ET 地址的服务证书。现有备份恢复路径包含插件包、秘密及数据库中的进度，不复制运行期 socket。

## 三个业务插件

### ET

适配已部署的 2.6.4 接口：会话登录、机器与实例查询、配置读取、定点修改、实例启停和状态读回。修改前读取上游原文，仅合并允许的变更字段，保留网络秘密，再验证、保存并核对结果。只有明确关联到 OPSD 节点的实例参与网络目录和后台采集，账号中的其他机器不自动登记为 OPSD 节点，也不因 STUN 上报加入公网来源集合；所选 ET 网段互信仍覆盖该网络中的其他成员。

### Docker／Portainer

Portainer Server 在指定 Hub 宿主节点运行，其他受管节点安装普通 Portainer Agent。缺少 Engine 和 Compose 时由向导明确允许安装；已有 Engine 不自动升级，补装 Compose 若需要改变现有 Docker 组件则停止。已有容器只盘点，既有 Compose 项目不从容器反推后自动接管。

首批页面集成容器、Stack、镜像、网络、卷、日志和终端。日常业务统一通过 Portainer，节点程序只负责安装与修复引导。重复安装核对自有标签、镜像、启动参数、实际挂载、权限和端口，复用容器身份，不隐式重建其他容器。

### Silo

部署前核对所有节点的 Docker 环境、实际 ET 地址、相同盘数及完整选择。新盘逐块核对设备、容量、序列号和使用痕迹，明确清空确认后准备 XFS 与持久挂载；已有路径不格式化，也不自动替换为其他设备。原存储适合度和拓扑分析已经迁入 Silo 插件。

先准备所有节点，再创建全部成员容器，最后等待集群健康。准备记录、UUID、挂载、成员容器和失败进度持久保存；恢复先核对实际状态。中断在格式化且未取得 UUID 时停止并要求核实，不盲目重新格式化。桶、用户和管理状态通过配套 mcli 执行，核对退出码与 JSON 状态，提交成功不计为执行成功。

| 服务 | 显式绑定 |
| --- | --- |
| Portainer Server | 控制机 ET 地址的 HTTPS 9443 |
| Portainer Agent | 节点 ET 地址的 9002 → 容器 9001 |
| Silo S3／Console | 各成员 ET 地址的 HTTPS 9000／9001 |

缺少 ET 地址时停止，不能回退到全部网卡。原生管理台由按钮在新标签页打开 ET 地址，使用各自登录。Portainer Server 和 Silo 使用节点生成、Hub CA 签发的证书；普通 Portainer Agent 沿用其原生自签名 TLS 与 AGENT_SECRET 协议，不能将这段连接宣传为 OPSD mTLS。原生管理台中的直接操作由上游记录，OPSD 不冒充拥有完整审计。

## 输出 API 与迁移

只保留根路径 /api/v1/public/nodes、/api/v1/public/summary 与 /api/v1/public/metrics，分别提供版本化 JSON 和 Prometheus。请求只使用一个独立只读 Bearer API Key，按节点范围与公开字段白名单输出，不携带内部地址、线路、插件秘密或管理字段。

分享页面、链接令牌、双凭据组合、独立分享构建和专属主题资源已退出。未知管理 API 返回 JSON 404，不回退成控制台 HTML。控制台完整前端接口版本升为 2，旧版本包保留文件但不能启用；不兼容的当前选择回到内置前端，样式覆盖仍可使用。

旧业务 Action 类型保留用于读取历史任务；未结束的旧 Docker／存储危险任务标记阻断，不重写成新插件任务。新 Agent 拒绝旧业务写入，核心旧执行模块已删除。旧 Agent 不被当作支持插件、双连接和自动互信，必须明确升级后才能使用这些能力。

### 首次安装

继续复用受控脚本、一次性令牌、CA 和固定发行元数据。安装成功仍以 Agent mTLS 的 GET /status 确认自身在线为准；已有身份不匹配时停止。安装链的既有四组合证据见 [Agent 一键安装](agent-installation.md)，该历史发行证据不等于本批重新发布或部署。

## 请求、延迟与成本

本批所有正常、重试和回退均为 **0 次模型请求**。身份、选路、白名单、恢复和业务适配均由确定性程序完成，没有新增运行时模型审查。

- 双连接各自保活；Agent 心跳 10 秒、Hub ping 15 秒，失联阈值 45 秒。只由当前首选线路发送常规指标；网卡事实每 30 秒采集，节点间两条路径每 60 秒探测。代价是多一条连接及每个对端最多多一次探测，收益是已有连接故障时能切换并保留同一任务身份。
- 公网与 ET 独立使用 1～30 秒连接退避。Agent 重启或外部规则重载后追赶最新版期望状态，不重放整串历史网络任务。
- ET 复用 Cookie 会话，GET 缓存 10 秒，后台每 30 秒只刷新已关联实例的配置与运行信息，每实例通常两次上游 GET。认证失效最多重新登录一次；写入超时或结果不确定时先核实上游，不盲目重写。
- 当前 Docker 页面一次刷新会并发取得容器、镜像、网络、卷及 Stack，因此实际为 **1 次 OPSD 请求 + 5 次 Portainer 请求**；随后切换标签复用这份结果。单独详情或日志为 1 次 OPSD 加 1 次上游请求。登录令牌复用，401 最多续会话一次；安装后首次登录每 2 秒等待，最多等待 60 秒。写入中断或 5xx 标为待核实。
- Silo 安装按节点进行依赖及磁盘预检、准备、证书、容器和健康查询，多步操作以任务记录与部署进度为准；不把它描述为一次 API 调用。mcli 命令至少经过 exec 创建、启动与退出状态查询。集群健康以 180 秒为收敛门限，单次查询超时 5 秒，每轮结束后等待 2 秒。首次依赖安装和镜像拉取的请求及耗时取决于包管理器、镜像层和节点数，不承诺固定为一次请求。
- 既有安装请求保持：生成信息 1 次 POST 加 1 次摘要 GET；复制或下载本地 Blob 不增加请求。宿主机下载 1 次、注册 1 次、每 2 秒查询状态，最多 30 次且总截止 60 秒；镜像拉取随层数变化。下载和注册不自动重试，重跑脚本复用已有身份。
