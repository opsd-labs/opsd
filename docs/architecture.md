# 架构说明

## 组件

```text
浏览器
  │ HTTPS + 安全入口 + 会话/CSRF
  ▼
Hub ─────────────── 控制库、任务、审计、聚合结果
  │
  │ 8444 / mTLS，Agent 主动连接
  ▼
Agent ───────────── 节点本机 Docker、主机、数据库和运维工具
```

Web 控制台和 Hub 一起发布。Hub 不需要进入节点网络主动连接 Agent，节点只需能够主动访问 Hub 的 mTLS 端口。

## Hub

Hub 提供：

- 管理员认证和会话；
- 安全入口门禁；
- Agent 注册、证书和节点目录；
- 任务下发、结果聚合和事件广播；
- 指标、数据库和存储结果的集中展示；
- 分享令牌、主题、审计以及备份恢复；
- HTTP API 和 Web 控制台静态资源。

默认控制台监听 `65535`，健康检查监听容器回环的 `65534`。健康检查不是外部管理入口。

## Agent

Agent 运行在被管理节点上，负责：

- 主动建立和维护 mTLS 连接；
- 采集主机、Docker、指标、数据库和存储事实；
- 在本机执行结构化任务；
- 使用节点上已有的权限和秘密文件；
- 将结果和错误原因返回 Hub。

Agent 不应将不必要的秘密上传 Hub。数据库巡检密码等凭据只在节点本地进入客户端进程环境。

### 首次安装

Hub 在已认证的注册信息创建请求中，将受控安装模板、公共 CA、一次性令牌和固定发行元数据组合为专属脚本。复制命令只是传递同一脚本；脚本与原始令牌只在本次响应返回，摘要列表不保存或返回它们。Hub 不为生成安装信息访问 GitHub，安装器在目标机下载固定发行包或镜像，随后复用现有注册协议与 systemd／Docker 常驻运行。

安装成功以 Agent mTLS 监听的 `GET /status` 确认自身在线为准。该接口复用证书身份与节点在线判定，不接受目标节点参数，不扩大控制台入口白名单。已有本机身份匹配时可继续启动；身份不匹配时保留原材料并停止。详细恢复边界和验证证据见 [Agent 一键安装](agent-installation.md)。

本阶段正常、重试和回退均为 **0 次模型请求**，所有步骤由程序确定执行。生成安装信息沿用 1 次 POST 和 1 次摘要 GET，复制与 Blob 下载不增加 HTTP 请求；客户端 SSE 合并刷新沿用原行为。宿主机正常安装产生 1 次发行包下载（可跟随 HTTPS 重定向）、1 次注册 POST，以及每 2 秒一次、最多 30 次且总截止 60 秒的状态查询；Docker 拉取请求数随镜像层数变化。下载和注册不自动重试，重复执行复用已保存身份；Agent 原有 1 至 30 秒的连接退避不变。

新增耗时主要来自依赖准备、程序下载和启动确认；Hub 生成脚本没有外部网络等待，也没有新增发行信息运行时缓存，创建响应使用 `no-store`。收益是消除手动安装程序、传输令牌与 CA、配置常驻服务的前置步骤，已由页面原样命令和下载脚本的真实安装验收证明。

## 数据流

1. 管理员在 Web 控制台发起查询或任务。
2. Hub 验证会话、CSRF、权限和请求结构。
3. Hub 通过对应 Agent 的 mTLS 通道下发结构化任务。
4. Agent 在本机执行固定动作或受控命令。
5. Hub 校验结果、记录审计并更新内存缓存或控制库。
6. Web 获取聚合后的结果，并明确区分未知、过期和异常。

## 信任边界

- 浏览器到 Hub：HTTPS、Origin、Cookie 和 CSRF 共同保护控制面。
- Agent 到 Hub：双向 TLS，注册前使用一次性短时令牌建立身份绑定。
- Hub 到节点：不存在反向 SSH 或 Docker socket 访问；节点侧执行由 Agent 负责。
- 公开分享面：只允许公开字段和专用令牌，不继承管理会话。
- 节点本地秘密：由 Agent 按权限读取，不进入 Hub 控制库和普通审计正文。

## 存储

默认控制库是 `data/control.db`。可通过 `OPSD_DATABASE_URL` 使用独立 MariaDB，但当前版本不支持在线跨库迁移，也未完成真实 MariaDB 回归。

运行期变化快的指标、数据库和主机盘点结果部分保留在 Hub 内存缓存中，并带采集时间；历史任务、控制记录和审计数据进入控制库。
