# 实施与验收记录

更新时间：2026-09-24。本文记录实际覆盖，不将代码存在等同于完成验收。

## 已验证

- Windows 原生主控与 Agent：TLS、登录、CSRF/Origin、一次性注册、证书续期后 mTLS 连接、幂等冲突、任务序号、采集任务、备份恢复重连与撤销。
- SQLite 重启任务持久化、跨节点幂等隔离、未知任务参数拒绝。
- 策略与回滚记录原子提交，模拟第二条记录写入失败时验证第一条记录也回退；管理 API 的任务配置正文脱敏。
- Linux Docker 实验室：原 Compose 导入不改变容器 ID；启停重启保持 ID 和挂载；非法 Compose 在计划阶段拒绝；外部 `.env` 变更阻止发布；Stack 移除保留命名卷。
- 防火墙渲染单元测试：仅清理受管链，保留 Docker 扩展入口；UFW 受管块替换保留块外内容。这不是内核网络验收。
- WSL 专用双网络命名空间：iptables-nft 真实 IPv4/IPv6 TCP 入站及出站、节点地址优先放行、非节点拒绝、外部规则保留。测试先验证所有探测源可达，再施加策略，防止将坏拓扑误判为拒绝成功；不覆盖 Docker 转发和独立回滚。
- 前端类型检查与生产构建；演示模式和移动端布局的基础浏览器测试；控制台、数据库、存储、防火墙四页的自动无障碍检查。
- 存储预检与存储集群部署：结论式报告、定义/计划/执行三段式、指纹与有效期、破坏性计划显式确认、
  逐节点串行失败阻断、节点侧格式化前二次核对现实（`verify_device`）在 Windows 与 WSL 上均通过测试。
- 数据库只读巡检：固定语句（不经过网络、不经过 shell）、只读账号密码文件权限校验、
  wsrep/ProxySQL/备份目录与定时器的纯解析函数、阈值与告警规则逐条对齐的结论层、
  「未知不等于 0」的展示口径。**这些都是解析与判定层面的验证，不是对真实 MariaDB 集群的验收。**
- 对端延迟探测：ICMP/TCP 两种方式、`ping` 输出解析、目标列表随目录版本化下发、
  「没测到不是 0」与「工具缺失 ≠ 网络不通」的区分、桶内按对端平均。**真实跨节点链路未测。**
- HTTP 契约：`docs/api/openapi.yaml`（55 路径 / 62 操作 / 138 类型）覆盖控制台、分享面、
  一次性注册与 Agent 续期/验证面；通过 OpenAPI 3.1 lint（0 error），`openapi-typescript`
  生成 `web/src/generated/api.ts`，并有生成物漂移检查；`npm run api` 一并执行这两项。
  前端 `web/src/api.ts` 的类型改为取自生成物。契约编写完成后经一次多模型交叉审计逐条对照源码，
  据此修正了 12 处事实性偏差（流通道 payload 编码、Agent 监听默认端口、文件操作请求体必填项、
  `peer-addresses` 可返回 null、202 总述与框架级错误正文等）。
  **这是契约自洽与源码一致性的验证，不是运行时验证。**

## 仍需完成，禁止视为生产就绪

- 四防火墙后端的真实 IPv4/IPv6、转发、Docker 重启、外部规则并发与默认策略验证；独立 Linux 虚拟机故障矩阵。
- systemd 回滚跨重启持久化、所有权漂移检测、回滚失败阻断后续全网发布。
- 逐条外部规则等价接管、CODEX_GALERA 及其 systemd/Ansible 维护来源交接。
- 节点地址集合与同步任务已在同一事务写入，目录改名不增加集合版本；仍需故障注入验证目录更新到任务生成之间的恢复，以及稳定公网地址自动发现与失败任务重试。
- 证书临近到期/长时间离线故障测试；任务报告已加入持久化序号，仍需完善完整事件补传、状态转换约束、缓存与历史查询上限。
- Docker 拉取实时进度、日志/终端断线与权限到期测试；Compose 多文件更新、上一版本再部署及发布端口探测。原目录与文件合并顺序已按 Docker Compose 标签核对。
- MariaDB 实机存储测试、容器镜像构建验证、部署配置和密钥统一备份、异机恢复故障测试。
- **数据库只读巡检未在真实 Galera 集群上跑过**：需要先确认 `db-inspect.json` 里的容器名、
  只读账号与密码文件路径与现场一致，再在单节点试点核对「采集到的值」与
  `mariadb -e` 手工查询一致，之后才谈集群视图。
- **存储集群部署未在真实节点上执行过**：格式化是不可逆操作，必须先在隔离实验室按
  「预检 → 生成计划 → 执行」完整走一遍，并验证中断与失败阻断行为。
- 十二生产节点真实只读盘点、低影响节点试点及连续 24 小时观察。
- **对端延迟只在同机与解析层面验证过**：真实跨节点 ICMP 是否被防火墙放行、
  `ping` 在各节点是否存在、覆盖网地址是否都登记，都需要在生产节点上先试点一台。
- **契约没有做真实响应的 schema 校验**：lint 与漂移检查只能保证契约自洽、生成物同步，
  发现不了「实现返回的正文与契约不符」。按计划还需要对真实响应做运行时校验。
- **契约对请求体的严格性强于实现**：Rust 侧只有 `Action` 与 `FileRequest` 设了
  `deny_unknown_fields`，其余请求结构体（登录、注册、任务提交、主机盘点、主题清单等）
  会静默忽略未知字段，而契约标了 `additionalProperties: false`。当前影响仅限生成类型的
  多余字段检查，尚未逐条订正。
- 交叉审计发现两处**实现**问题，尚未修复（不是契约问题，契约已按现实描述）：
  1. `src/hub/share.rs` 的 `authorize_key` 先写 `key.last_used = Some(now())` 再判断是否超过 60 秒，
     条件恒假，`last_used` 永远不会写回控制库；
  2. `src/hub/share.rs` 的公开节点 `metrics_at` 取的是「最近一次上报」的接收时刻（采集失败也会刷新），
     而界面把它当作「最近一次成功采样」的新鲜度指示，指向相反。

新增部署文件已通过 `docker compose config --quiet`，完整镜像构建尚未验证。前端已接入新建 Stack 的部署计划以及容器实时详情任务。

默认构建在执行防火墙计划时明确拒绝写入，避免把未验证实现带入生产。仅实验室可使用 `cargo build --features experimental-firewall`；WSL 各发行版共享内核/网络，必须先创建专用网络命名空间，回滚单元也须进入相同命名空间，不能直接在 WSL 默认网络执行测试。

## 重放 Docker 实验

仅在专用实验 Docker Engine 中运行，测试创建带随机 `opsd-test-` 前缀的项目并清理自身资源。

```bash
OPSD_LAB=1 python3 tests/prepare-docker-lab.py
OPSD_LAB=1 cargo test --bin opsd-agent -- --ignored --nocapture
```

镜像由实验机的 shell、sleep 和动态库离线构造，不需要拉取 Docker Hub。测试明确断言失败路径，不将错误响应计作空资源或成功。
